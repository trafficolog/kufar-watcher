# Стратегия тестирования — Kufar Monitor

## Принцип

Тесты пишутся против поведения из карточки задачи, а не против реализации.
Основной риск проекта — не падение приложения, а **тихая неправильная работа**:
монитор молчит, потому что сломался разбор ответа, а не потому что нет новых
объявлений. Поэтому приоритет — на детерминированные тесты ядра и на проверки
целостности данных, а не на покрытие UI.

## Уровни

| Уровень | Инструмент | Что покрывает |
|---------|-----------|---------------|
| Unit (TDD) | Vitest | URL-парсер, лимитер, водяной знак, стеммер и маски, матчер |
| Integration | Vitest + Postgres в Docker | Prisma-репозитории, идемпотентность записи, pg-boss-джобы |
| Contract | Vitest на зафиксированных фикстурах | нормализация ответов адаптеров, детект дрейфа схемы |
| E2E | Playwright (Electron) | сценарии панели управления и приёмка MVP-1 |

## Обязательный TDD

Тесты пишутся до кода для модулей, где ошибка не видна глазом:

- `1.1.1`, `1.1.2` — разбор и сборка URL
- `1.2.1` — лимитер запросов
- `1.4.1` — водяной знак новизны
- `2.1.x` — морфология и glob-маски
- `2.2.x` — матчер ключевых слов

## Фикстуры вместо сети

Ни один автотест не ходит в kufar.by. Сырые ответы площадки сохраняются в
`tests/fixtures/kufar/` вместе с датой снятия. Обновление фикстур — отдельная
ручная процедура, её результат разбирается в задачах эпика 4.1: расхождение
свежего ответа с фикстурой и есть тот самый дрейф схемы.

## Где живые запросы всё-таки допустимы

Правило «без сети» относится к автотестам, а не к работе человека. Живые запросы
выполняются вручную, поштучно, с соблюдением лимитера, в трёх местах:

- эпик `1.0` — разведка контракта, снятие исходных фикстур;
- задачи `1.3.2`, `1.3.3`, `1.3.4` — сверка нормализации с фактическим ответом;
- задача `5.6` — приёмочный прогон на реальных ссылках.

Ни один из этих запросов не выполняется автоматически в составе тестового
прогона и не попадает в CI.

## Чекпоинт задачи

typecheck 0 ошибок · lint 0 ошибок · unit зелёные · integration зелёные (где
применимо) · `npm run docs:ops:check` проходит.
