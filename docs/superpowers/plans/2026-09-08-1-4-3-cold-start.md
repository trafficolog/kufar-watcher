# 1.4.3 Cold Start Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish a bounded first-run baseline for new monitors without creating matches or notifications, then route later cycles through the existing incremental path.

**Architecture:** Add a pure cold-start traversal for top-edge tie closure, a cold-start persistence transaction with monitor/source/cursor stale preconditions, and a `runMonitorCycle` router that chooses cold vs incremental while preserving `runIncrementalMonitor` unchanged as the initialized path.

**Tech Stack:** TypeScript strict, Vitest, Prisma 7, PostgreSQL 16.

**Spec:** `docs/superpowers/specs/2026-09-08-1-4-3-cold-start-design.md`

## Global Constraints

- All source requests go through `SourceAdapter`.
- `maxPages` is mandatory and >= 1.
- No `Match` or notification work on cold start.
- Incomplete top-time tie commits nothing.
- Network traversal stays outside the Prisma transaction.
- Cold-start commit locks `Monitor` and validates source identity plus cursor initialization before writes.
