# Spec — контракт площадки kufar.by

> Статус: **черновик по открытым источникам.** Всё, что помечено «требует
> проверки», проверяется в задаче `1.3.2` на живом ответе и фиксируется
> фикстурой в `tests/fixtures/kufar/`. Не считать этот документ истиной —
> считать гипотезой, которую первая же задача фазы 1 подтверждает или правит.

## Основной канал

Сайт работает поверх собственного JSON-API. Это первичный источник; HTML —
только фолбэк.

| Категория | Хост поисковой выдачи |
|-----------|----------------------|
| Недвижимость | `cre-api.kufar.by` — **требует проверки**; у площадки есть и пользовательский поддомен недвижимости, это разные вещи |
| Электроника и прочие товары | хост того же семейства, **требует проверки** |
| Авто | `auto.kufar.by` — вне периметра проекта |

Пользовательские адреса живут на нескольких поддоменах, и ссылка, которую
вставит пользователь, может прийти с любого из них либо через переадресацию.
Нормализатор адресов обязан это выдерживать, а не предполагать единственный
`www.kufar.by`. Конкретный перечень поддоменов уточняется в эпике `1.0`.

Путь выдачи: `/ads-search/v1/engine/v1/search/rendered-paginated`
Парный счётчик: `/ads-search/v1/engine/v1/search/count`

## Параметры запроса

| Параметр | Значение |
|----------|----------|
| `query` | поисковая строка (соответствует сегменту `q~…` в адресе сайта) |
| `cat` | идентификатор категории |
| `rgn` | регион; отсутствие означает всю Беларусь |
| `ar` | область/район внутри региона |
| `sort` | `lst.d` — по дате размещения, убывание |
| `size` | размер страницы |
| `cursor` | курсор следующей страницы (keyset-пагинация) — **обязателен к поддержке**, см. ниже |
| `cur` | валюта |
| `lang` | язык |
| `ot` | тип владельца; предположительно это и есть «без посредников», **требует проверки** |

Сегменты человеческого адреса (`/l/bez-posrednikov/`, `q~playstation-4-pro`)
отображаются на эти параметры. Задача `1.1.1` строит это отображение.

## Пагинация обязательна

Соблазн ограничиться первой страницей выдачи выглядит разумно: при минутном
интервале новых объявлений между обходами единицы. Но первая страница
переполняется всякий раз, когда обходы прерывались — перезапуск приложения,
сон машины, недоступность Docker, сбой сети, всплеск публикаций в популярной
категории. В этот момент водяной знак оказывается за пределами первой страницы,
и монитор молча теряет всё, что между ними. Внешне он при этом здоров.

Поэтому адаптер обязан уметь идти по курсору вглубь, а водяной знак — этим
пользоваться. Догоняющий обход после сна (эпик 2.5) без этого не реализуем в
принципе.

### Что проверить про порядок выдачи

Отдельно выяснить в разведке: гарантирует ли площадка вторичный порядок при
одинаковом времени размещения. Если нет — алгоритм водяного знака не имеет права
на него опираться и обязан проходить всю временную границу целиком, отбрасывая
уже виденные идентификаторы. Задача `1.4.1` спроектирована именно так, то есть
не зависит от ответа; но знать его всё равно нужно.

## Цена бывает не числом

У площадки есть объявления с договорной ценой, то есть без обычного числового
значения. Модель обязана это различать с самого начала: поле цены nullable, вид
цены — отдельное перечисление. Переход между видами (`150 BYN` → договорная и
обратно) считается изменением цены и порождает уведомление.

## Сопутствующие эндпоинты

- Информация о продавце: `www.kufar.by/item/api/aduserinfo/{user_id}`
- Изображения: `yams.kufar.by/api/v1/kufar-ads/images/{XX}/{id}.jpg?rule=gallery|line_thumbs`,
  где `XX` — первые два символа имени файла. В MVP не используется: уведомления текстовые.
- Список категорий: существует, точный путь **требует проверки**. Нужен Post-MVP
  (конструктор фильтров), в срезе MVP-1 не вызывается.

## Что нужно от ответа выдачи

Минимальный набор полей, без которого система не работает. Имена в ответе
площадки **требуют проверки** — сопоставление делается в задаче `1.3.2`:

| Домен | Смысл | Критичность |
|-------|-------|-------------|
| `listId` | идентификатор объявления | обязательно: на нём держится дедупликация |
| `listTime` | время размещения | обязательно: на нём держится водяной знак |
| `title` | заголовок | обязательно |
| `price` + валюта | цена | обязательно |
| `accountId` | идентификатор продавца | нужно для чёрного списка |
| признак юрлица | частник или компания | нужно для фильтра продавца |
| регион | область/город | желательно, идёт в уведомление |
| краткое описание | усечённый текст | опционально; полный текст — отдельным запросом |

## Уровни деградации

1. **JSON-API** — основной путь.
2. **Встроенные данные HTML-страницы.** Сайт отдаёт состояние страницы внутри
   разметки; при недоступности API его можно извлечь оттуда. Конкретный
   механизм **требует проверки** в задаче `1.3.4`.
3. **Разбор DOM** — последний рубеж, Post-MVP.

Переключение уровня — событие, о котором пользователь узнаёт: работа на втором
уровне считается деградацией и отражается на экране здоровья.

## Порядок работ

Этот документ проверяется **до** того, как по нему что-либо проектируется.
Эпик `1.0` выполняется первым в фазе 1: снимаются живые ответы, сверяются имена
полей, поведение курсора, поддомены и наличие `/count`. Только после этого
пишется нормализатор адресов.

Отдельно учесть: внешние обращения к страницам площадки могут получать отказ в
доступе в зависимости от того, как выполнен запрос. Это ещё одна причина не
проектировать сетевой слой по догадкам, а начать с разведки.

## Правила обращения

- Единый лимитер на весь процесс, с джиттером. Ориентир — не чаще одного
  запроса в 2–5 секунд суммарно ко всем хостам площадки.
- Обходы разных мониторов не выполняются одновременно.
- Классификация ошибок едина для всего проекта и повторена здесь, чтобы
  источник истины не расходился:
  - **`429`** — увеличить паузу, снизить частоту, записать событие здоровья.
    Ретраи и фолбэк запрещены: смена канала ради продолжения запросов и есть
    обход только что выставленного ограничения.
  - **сеть, таймаут, `5xx`** — ограниченные ретраи с экспоненциальной задержкой;
    после их исчерпания допустим фолбэк, прошедший проверку структуры.
  - **дрейф схемы** — пауза монитора и алерт. Фолбэк запрещён: он подменяет
    пользователю диагноз.
- Работа анонимная, без входа в аккаунт.
