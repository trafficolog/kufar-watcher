# Эпик 5.0 — Минимальный пользовательский срез

## Цель

Дать пользователю возможность пройти сценарий целиком, не открывая базу и не
редактируя файлы: создать монитор, настроить Telegram, получить уведомление.

## Контекст

Без этого эпика срез `0.3.0` не является MVP. Бэкенд доходит до отправки
сообщения, но создать правило и ввести токен бота негде: полноценный редактор
живёт в `5.2`, настройки — в `5.4`, оба приходят позже. При этом конституция
проекта прямо запрещает считать `.env` пользовательским способом хранения токена.

Эпик намеренно минимальный. `5.2` и `5.4` потом расширяют эти же экраны, а не
заменяют их.

## Планируемые задачи

- `5.0.1` — Быстрое создание монитора: имя, ссылка, интервал, ключевые слова
- `5.0.2` — Настройка Telegram: ввод токена и привязка разрешённого чата
- `5.0.3` — Минимальный список мониторов с состоянием последнего обхода
- `5.0.4` — Приёмка среза MVP-1 сквозным сценарием

## Критерии приёмки эпика

- [ ] Пользователь проходит путь «запустил → ввёл токен → создал монитор → получил уведомление», не открывая базу и не редактируя файлы (установочные пакеты появляются в `5.7`)
- [ ] На Windows токен хранится в защищённом хранилище учётных данных ОС
- [ ] На Linux приложение определяет выбранный бэкенд хранилища; при отсутствии защищённого пользователь получает явное предупреждение, а не молчаливое сохранение в открытом виде
- [ ] Токен не пишется в журнал ни на одном уровне логирования
- [ ] Бот игнорирует сообщения и нажатия из чатов, кроме привязанного
