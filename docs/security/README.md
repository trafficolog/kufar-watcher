# Security — Kufar Monitor

Приложение локальное, однопользовательское, без входящих сетевых портов, поэтому
классическая поверхность атаки узкая. Но Electron — это браузер с доступом к
файловой системе, и часть требований не следует из «локальности» никак.

## Обязательные настройки окна

| Требование | Почему |
|-----------|--------|
| `contextIsolation: true`, `nodeIntegration: false` | иначе любой скрипт в renderer получает Node |
| `sandbox: true` для окна | ограничивает процесс renderer уровнем ОС |
| Жёсткая политика содержимого | без неё сторонний скрипт исполняется без препятствий |
| Запрет перехода на внешние адреса внутри окна | окно приложения не должно превращаться в браузер |
| Запрет открытия новых окон, кроме явно разрешённых | всплывающее окно с внешним содержимым обходит все ограничения выше |
| Проверка отправителя каждого сообщения IPC | обработчик обязан убедиться, что запрос пришёл из своего окна |

## Открытие внешних ссылок

Renderer **не передаёт адрес наружу**. Мост принимает только идентификатор:

```
openListing(listingId)
  → main достаёт объявление из базы
  → строит адрес
  → проверяет: протокол https, домен из списка доменов площадки
  → открывает во внешнем браузере
```

Передача произвольного адреса в системный обработчик — известный способ
выполнить постороннюю команду. Идентификатор такой возможности не даёт.

## Шрифты и сторонние ресурсы

Прототипы подключают шрифт из внешней сети — это допустимо для макета и
недопустимо в сборке. В приложении шрифт лежит рядом с кодом либо берётся
системный. Иначе политика содержимого вынужденно ослабляется ради одного
запроса, а приложение при отсутствии сети выглядит сломанным.

## Данные площадки

Заголовки, описания и имена продавцов — недоверенный ввод. Валидировать перед
записью, выводить интерполяцией, `v-html` не использовать. В сообщениях Telegram
экранировать спецсимволы разметки.

## Доступ к Docker

Управление контейнером базы через демон Docker — привилегированный системный
интерфейс, а не обычная локальная служба: доступ к нему равносилен возможности
запускать контейнеры от имени пользователя. Приложение обращается к нему только
для своего контейнера, по имени, и не принимает имя контейнера снаружи.

## Секреты и данные

| Риск | Смягчение |
|------|-----------|
| Утечка токена бота | системное хранилище учётных данных, не файл; в журнал не пишется ни на одном уровне; на Linux при отсутствии защищённого хранилища человек предупреждается явно |
| Команды из чужого чата | бот игнорирует всё, кроме привязанного чата |
| Доступ к базе с машины | порт публикуется только на локальном адресе, пароль генерируется при установке |
| Раскрытие истории интересов | данные остаются локально и наружу не уходят |

## Когда проводить полный разбор угроз

Перед Post-MVP-этапом переписки с продавцом: появляется авторизация в аккаунте
площадки и исходящие сообщения, и поверхность атаки меняется качественно.
