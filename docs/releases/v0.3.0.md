## Обещание среза

MVP-1 замыкает первый пользовательский вертикальный сценарий внутри приложения:

**ссылка Kufar + интервал + простые ключевые слова / glob-маски → регулярный
обход → отбор новых объявлений → уведомление в привязанный Telegram-чат.**

Пользователь должен настроить Telegram, создать монитор и увидеть его состояние
из окна приложения, не редактируя базу или конфигурационные файлы вручную.

## Scope `0.3.0`

В релиз входят:

- URL parsing / canonical query и category routing (`1.1`);
- HTTP client, rate limiting и raw-response journal (`1.2`);
- обязательные source adapters Electronics и Real Estate (`1.3.1–1.3.3`);
- watermark, persistence, cold start и catch-up checkpoint (`1.4`);
- нормализация текста, литеральные термы и glob-маски (`2.1`);
- include/exclude matcher и интеграция матчера в обход (`2.2`);
- персональные расписания, no-overlap, Run journal и retry/degraded behavior
  (`2.4`);
- Telegram long-polling transport, reconnect и outgoing queue (`3.1`);
- сообщение, кнопка «Открыть» и идемпотентная доставка (`3.2.1–3.2.3`);
- минимальный UI: создание монитора, Telegram setup, список мониторов и
  сквозная acceptance (`5.0`);
- first-run state (`5.8.2`).

Задачи, реализованные раньше своего delivery slice, не расширяют этот список и
не меняют acceptance promise `0.3.0`.

## Acceptance gate MVP-1

Финальная пользовательская проверка определяется карточкой `5.0.4` и должна
подтвердить как минимум:

- чистый профиль позволяет настроить Telegram и создать монитор без доступа к
  базе или файлам;
- первый обход служит baseline и не рассылает старые объявления;
- новое подходящее объявление приводит к Telegram-уведомлению с рабочей кнопкой
  «Открыть»;
- перезапуск приложения не ломает восстановление расписаний и обработку новых
  находок;
- ручное наблюдение не выявляет необъяснимых пропусков; возможные повторы
  объясняются persisted delivery state / journal evidence.

Installer acceptance на чистой машине в `0.3.0` не требуется: packaging входит
в более поздний delivery slice.

## Известные ограничения / не-цели

MVP-1 намеренно **не обещает**:

- морфологический поиск по словоформам (`2.6`);
- seller blacklist и seller filtering (`0.3.4`, `2.3`);
- тихие часы и power/sleep catch-up (`2.5`, `3.3`);
- кнопку «В избранное», историю цен и price watch (`3.2.4`, `3.4`);
- полноценные Feed / Favorites / Archive / Settings workflows (`5.3`, `5.4`);
- health/canary/autopause UI (`4.x`, `5.5`);
- полноценную dashboard board (`5.8.1`);
- установочные пакеты Windows/Linux, автозапуск и финальный packaging (`5.7`).

Некоторые внутренние возможности будущих срезов уже могут присутствовать в
`main`; это не делает их частью release contract `0.3.0` без отдельного решения
по ROADMAP.

## Verification

Финальное verification evidence **ещё не зафиксировано**, потому что релиз не
закрыт. Каждая входящая task-карточка должна проходить обычный CI gate, а перед
release PR выполняется полный pipeline: documentation consistency, unit tests,
CI failure-mode self-check, typecheck, lint, formatting, PostgreSQL integration,
build/output verification и применимые Electron smoke checks.

Exact final run number и release commit записываются здесь только после их
фактического успешного выполнения.
