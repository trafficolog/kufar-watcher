# Задача 5.0.2 — Настройка Telegram: токен и привязка чата

> Эпик 5.0 · Фаза 5 · ⬜ todo · зависит от: 3.1.1 · оценка: 4-5 ч

## Цель

Экран ввода токена бота и привязки разрешённого чата, с честным поведением при недоступном защищённом хранилище.

## Контекст

Конституция проекта запрещает считать `.env` пользовательским способом хранения токена, поэтому без этого экрана срез не замыкается. Отдельная сложность — Linux: штатное защищённое хранилище Electron опирается на системный сервис секретов и при его отсутствии молча деградирует до хранения без реального шифрования. Обещать пользователю защиту, которой нет, недопустимо.

## Что должно быть сделано

- Форма ввода токена с проверкой его работоспособности запросом к Telegram
- Мастер привязки чата: дождаться сообщения боту, показать найденного кандидата
  (имя и чат) и привязать только после нажатия «Привязать» в окне приложения
- Определять выбранный бэкенд защищённого хранилища при старте
- Если защищённое хранилище недоступно, показать явное предупреждение с объяснением и потребовать осознанного подтверждения перед сохранением; не называть такое хранение защищённым
- Кнопка проверки: отправить тестовое сообщение в привязанный чат

## Критерии приёмки

- [ ] Токен вводится и проверяется из окна приложения
- [ ] Привязка чата проходит без ручного поиска идентификатора
- [ ] Кандидат виден человеку до привязки и привязывается только по нажатию
- [ ] На Windows токен сохраняется в защищённом хранилище ОС
- [ ] На Linux при отсутствии защищённого бэкенда пользователь предупреждён явно, а не введён в заблуждение
- [ ] Тестовое сообщение доходит
- [ ] Токен не попадает в журнал

## Не делать
