# Задача 5.0.2 — Настройка Telegram: токен и привязка чата

> Эпик 5.0 · Фаза 5 · 🔄 in_progress · зависит от: 3.1.1 · оценка: 4-5 ч

## Цель

Экран ввода токена бота и привязки разрешённого чата, с честным поведением при недоступном защищённом хранилище.

## Контекст

Конституция проекта запрещает считать `.env` пользовательским способом хранения токена, поэтому без этого экрана срез не замыкается. Отдельная сложность — Linux: штатное защищённое хранилище Electron опирается на системный сервис секретов и при его отсутствии молча деградирует до хранения без реального шифрования. Обещать пользователю защиту, которой нет, недопустимо.

## Что должно быть сделано

- Форма ввода токена с проверкой его работоспособности запросом к Telegram
- Мастер привязки чата: дождаться сообщения боту, показать найденного кандидата
  (имя и чат) и привязать только после нажатия «Привязать» в окне приложения
- Определять выбранный бэкенд защищённого хранилища при старте
- Если защищённое хранилище недоступно, показать явное предупреждение с объяснением и потребовать осознанного подтверждения перед сохранением; не называть такое хранение защищённым
- Кнопка проверки: отправить тестовое сообщение в привязанный чат

## Критерии приёмки

- [x] Токен вводится и проверяется из окна приложения
- [x] Привязка чата проходит без ручного поиска идентификатора
- [x] Кандидат виден человеку до привязки и привязывается только по нажатию
- [ ] На Windows токен сохраняется в защищённом хранилище ОС
- [x] На Linux при отсутствии защищённого бэкенда пользователь предупреждён явно, а не введён в заблуждение
- [ ] Тестовое сообщение доходит
- [x] Токен не попадает в журнал

## Результат

- `/settings` содержит Telegram setup flow: проверка токена через Telegram, сохранение секрета, отображение найденного кандидата, явное подтверждение привязки и отправка тестового сообщения.
- Renderer не принимает и не передаёт `chatId`: candidate и bound chat остаются внутри main/worker boundary, а IPC-команды привязки и тестовой отправки не несут пользовательский идентификатор чата.
- Токен сохраняется через Electron `safeStorage`; Linux `basic_text` распознаётся как незашифрованный backend и требует отдельного осознанного подтверждения пользователя перед записью.
- Токен очищается из UI после сохранения или отмены, исключения не выводятся пользователю как raw errors, а тесты redaction подтверждают отсутствие токена в журнале.
- GitHub Actions `verify` #1697 на `e54dcc052521f48cb5a56629689f00c0df3513d2` полностью GREEN: 649 unit-тестов, docs check, typecheck, lint, formatting, Dockerode/PostgreSQL integrations, build и development/production Electron launch smokes.
- До `done` остаются два live-gate, которые CI не может честно заменить: проверка реального защищённого OS storage на Windows и подтверждение доставки тестового сообщения через настоящий Telegram bot/chat.
