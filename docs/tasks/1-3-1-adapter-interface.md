# Задача 1.3.1 — Интерфейс SourceAdapter и реестр

> Эпик 1.3 · Фаза 1 · ✅ done · зависит от: 1.1.3, 1.2.2 · оценка: 2-3 ч

## Цель

Единый интерфейс адаптера выдачи и реестр, по которому правило получает свой адаптер.

## Контекст

Категории различаются хостом, набором параметров и составом полей. Интерфейс прячет эти различия, чтобы конвейер обхода не знал, с какой категорией работает.

## Что должно быть сделано

- Описать интерфейс: получить страницу выдачи по `CanonicalQuery` и курсору, вернуть нормализованные объявления и курсор следующей страницы
- Описать нормализованную модель `Listing` в общем модуле типов
- Реализовать реестр адаптеров с выбором по категории

## Критерии приёмки

- [x] Интерфейс не содержит понятий, специфичных для одной категории
- [x] Реестр возвращает адаптер по результату `1.1.3`
- [x] Компиляция проходит с обоими адаптерами-заглушками

## Результат — 2026-09-08

- Общий `Listing` и `SourceAdapter` не содержат категорийных или Prisma-зависимых типов.
- Registry выбирает injected adapter по `KufarAdapterKind`, полученному из существующего routing слоя.
- Electronics и real-estate stubs компилируются и работают через один контракт; конкретные adapters остаются задачами `1.3.2` и `1.3.3`.
