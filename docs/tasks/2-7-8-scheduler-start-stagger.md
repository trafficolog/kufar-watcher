# Задача 2.7.8 — Детерминированное разнесение стартов мониторов

## Проблема

Одинаковые cron expressions выравнивают мониторы по стенному времени. Несколько правил могут одновременно создать burst работы, после чего общий limiter вынужден сериализовать очередь.

## Что сделать

- Перед изменением scheduler измерить, достаточно ли существующего global request limiter/jitter для внешней нагрузки.
- Если burst на уровне jobs остаётся значимым, ввести стабильный per-monitor offset/stagger без изменения пользовательского `intervalSec`.
- Offset должен быть детерминированным и устойчивым к restart, без накопительного дрейфа.

## Критерии приёмки

- [ ] Characterization фиксирует одновременные старты нескольких одинаковых расписаний.
- [ ] Решение не изменяет среднюю заданную частоту каждого монитора.
- [ ] После restart monitor сохраняет тот же offset.
- [ ] Пять мониторов не стартуют одним burst, если scheduler primitive позволяет разнесение безопасно.
- [ ] Если актуальная pg-boss/cron семантика не позволяет это без несоразмерной сложности, карточка закрывается только с измерением нагрузки и явным доказательством достаточности существующего limiter, а не предположением.

## Не делать

- Не вводить adaptive interval/backoff между schedule slots.
