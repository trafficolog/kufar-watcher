# Задача 1.2.3 — Журнал сырых ответов для отладки дрейфа

> Эпик 1.2 · Фаза 1 · ⬜ todo · зависит от: 1.2.2 · оценка: 2-3 ч

## Цель

Сохранять сырые ответы площадки с ограничением по объёму, чтобы при изменении структуры было что сравнивать.

## Контекст

Когда монитор сломается, вопрос будет один: что именно поменялось в ответе. Без сохранённого снимка ответ на него получить невозможно, а воспроизвести ситуацию нельзя — площадка уже другая.

## Что должно быть сделано

- Сохранять последний успешный ответ по каждому эндпоинту
- Ограничить хранение: несколько последних снимков, старые вытесняются
- Добавить экспорт снимка в файл для превращения в тестовую фикстуру

## Критерии приёмки

- [ ] После обхода в хранилище есть сырой ответ
- [ ] Объём хранения ограничен и не растёт бесконечно
- [ ] Снимок экспортируется в формат, пригодный для `tests/fixtures/kufar/`

## Подсказки

- Общий контекст — в карточке эпика и в `docs/AGENTS.md`

## Не делать

- Не реализовывать сравнение снимков — это эпик 4.1
