# Задача 1.3.4 — Фолбэк на встроенные данные HTML-страницы

> Эпик 1.3 · Фаза 1 · ⬜ todo · зависит от: 1.3.2 · оценка: 4-5 ч

## Цель

Второй уровень деградации: при недоступности JSON-API извлекать те же данные из состояния, встроенного в HTML-страницу.

## Контекст

Уровень нужен не для повседневной работы, а чтобы пятиминутная недоступность API не останавливала мониторинг. Граница проведена сознательно: **временный сбой лечится фолбэком, дрейф схемы — паузой**. Если смешать эти случаи, получится либо остановка мониторинга из-за сетевого сбоя, либо продолжение работы на изменившейся площадке с неверными данными.

Переход на фолбэк — событие, о котором пользователь узнаёт: молчаливая деградация недопустима.

## Что должно быть сделано

- Проверить на живой странице, в каком виде состояние встроено в разметку, и зафиксировать это в спеке контракта
- Реализовать извлечение и нормализацию в ту же модель `Listing`
- Реализовать переключение на фолбэк **только при временном сбое** основного
  канала: сетевая ошибка, таймаут, `5xx`
- Не переключаться на фолбэк при `429`: ограничение темпа лечится паузой, а не
  сменой канала
- Не переключаться на фолбэк при изменении структуры ответа: дрейф приводит к
  паузе монитора (эпик 4.3)
- Прогонять результат фолбэка через ту же проверку структуры и осмысленности,
  что и основной канал
- Помечать результат признаком деградации и публиковать событие
- Снять фикстуру HTML-страницы и покрыть извлечение тестами

## Критерии приёмки

- [ ] При временном сбое API обход завершается успешно через фолбэк
- [ ] При изменившейся структуре ответа фолбэк не используется, монитор уходит в паузу
- [ ] При `429` фолбэк не используется
- [ ] Если результат фолбэка сам не проходит проверку структуры, обход считается неуспешным: монитор уходит в паузу с алертом, а не отдаёт мусор
- [ ] Результат помечен как полученный на деградированном уровне
- [ ] Событие деградации попадает в журнал
- [ ] Тесты работают на сохранённой фикстуре

## Подсказки

- Общий контекст — в карточке эпика и в `docs/AGENTS.md`

## Не делать

- Не реализовывать разбор DOM как третий уровень: это Post-MVP
- Не делать фолбэк основным путём даже временно
- Не лечить фолбэком дрейф схемы: это подменяет пользователю диагноз
