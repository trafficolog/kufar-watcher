# Задача 3.2.3 — Гарантия доставки уведомления

> Эпик 3.2 · Фаза 3 · ⬜ todo · зависит от: 3.2.2 · оценка: 2-3 ч

## Цель

Одно совпадение не теряется никогда и не дублируется при обычных повторах. В одном узком случае дубль допускается осознанно.

## Контекст

Здесь важно не пообещать невозможного. Bot API не принимает ключ идемпотентности от клиента: отправив запрос и не дождавшись ответа, приложение не может выяснить, приняла ли его удалённая сторона. Остаётся окно, в котором сообщение ушло, процесс упал до записи отметки, и после перезапуска ситуация неотличима от неотправленного.

Значит, выбор такой: либо при неопределённости не отправлять и иногда терять объявление, либо отправлять и иногда прислать дубль. Для монитора объявлений верно второе — **редкий дубль лучше молча потерянной находки**, ради которой всё и построено.

Поэтому гарантия здесь — устойчивая очередь и доставка не менее одного раза. Обычные повторы, ретраи и перезапуски дублей не создают; дубль возможен только в этом узком окне.

## Что должно быть сделано

- Использовать `Match.notifiedAt` как признак доставки
- Отметку писать сразу после подтверждения от Telegram, отдельной короткой транзакцией
- Ввести промежуточное состояние `sending` со временем начала: после перезапуска запись
  в нём считается неопределённой и отправляется повторно
- Записывать в журнал каждый случай повторной отправки из неопределённого состояния —
  так редкий дубль объясним, а не выглядит дефектом
- Покрыть интеграционными тестами: повторный запуск отправителя, падение до отправки,
  падение между отправкой и отметкой

## Критерии приёмки

- [ ] Повторный запуск отправителя не создаёт дублей для доставленных совпадений
- [ ] Падение до отправки приводит к доставке после перезапуска, а не к потере
- [ ] Падение между отправкой и отметкой может дать один повтор — это ожидаемое поведение, зафиксированное в журнале
- [ ] Ни один сценарий не приводит к потере совпадения
- [ ] Интеграционные тесты на все три сценария зелёные

## Не делать

- Не реализовывать дедупликацию по содержимому сообщения: ключ строится по идентификаторам
- Не обещать доставку ровно один раз: Bot API этого не позволяет, и обещание в коде обернётся потерей находок
