# Задача 0.3.2 — Индексы и ограничения целостности

> Эпик 0.3 · Фаза 0 · ✅ done · зависит от: 0.3.1 · оценка: 2 ч

## Цель

Добавить индексы под горячие запросы и ограничения, защищающие от дублей.

## Контекст

Объём данных небольшой, поэтому речь не о производительности, а о корректности: уникальность связи монитор–объявление — это то, что физически не даёт прислать одно уведомление дважды.

## Что должно быть сделано

- Добавить уникальное ограничение на пару `monitorId` + `listingId` в `Match`
- Добавить индексы, перечисленные в спецификации доменной модели
- Добавить внешние ключи с осмысленным поведением при удалении монитора
- Сгенерировать миграцию

## Критерии приёмки

- [x] Повторная вставка той же пары монитор–объявление отклоняется базой
- [x] Удаление монитора не оставляет висящих записей
- [x] Миграция применяется поверх предыдущей

## Подсказки

- Общий контекст — в карточке эпика и в `docs/AGENTS.md`

## Не делать

- Не заниматься оптимизацией планов запросов: объём данных этого не требует
