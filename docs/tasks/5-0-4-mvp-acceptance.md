# Задача 5.0.4 — Приёмка среза MVP-1

> Эпик 5.0 · Фаза 5 · ⬜ todo · зависит от: 5.0.3, 5.0.2, 3.2.3 · оценка: 2-3 ч

## Цель

Пройти два сквозных сценария на реальных ссылках — один для поддерживаемого
маршрута «Игры и приставки» и один для поддерживаемого маршрута «Квартиры» — и
зафиксировать, что весь заявленный MVP perimeter готов.

## Контекст

Точка, ради которой строился весь срез. Приёмка проверяет не отдельные задачи, а то, что цепочка работает целиком в руках пользователя, а не в тестах.

Релиз `1.0.0` гарантирует поддержку только двух подтверждённых route/category
mappings: `kufar.by` / `www.kufar.by` + `igry-i-pristavki` через adapter kind
`electronics` и `re.kufar.by` + `kvartiru` через adapter kind `real-estate`.
Названия adapter kinds не означают поддержку всей электроники или всей
недвижимости. Прохождение сценария только по одному mapping не закрывает эту
задачу и не должно интерпретироваться как поддержка остальных категорий Kufar.

## Что должно быть сделано

- Пройти сценарий вручную на чистом профиле данных приложения (пустая база,
  пустое хранилище секретов): ввести токен, привязать чат, создать один монитор
  по реальной ссылке `igry-i-pristavki` и один монитор по реальной ссылке
  `re.kufar.by/.../kvartiru`, дождаться нового объявления в каждом сценарии,
  получить уведомление и открыть его кнопкой
- Использовать ссылки, которые проходят текущий production routing; базовые
  подтверждённые examples —
  `https://www.kufar.by/l/r~minsk/igry-i-pristavki/q~ps5` и
  `https://re.kufar.by/l/minsk/kupit/kvartiru`
- Проверить холодный старт для обоих поддерживаемых mappings: создание каждого
  монитора не порождает пачку уведомлений о старых объявлениях
- Проверить перезапуск приложения с обоими активными мониторами: расписания
  восстанавливаются, ни одна находка не потеряна
- Оставить два монитора на несколько часов — ровно по одному на
  `igry-i-pristavki` и `kvartiru` — и сверить полученные уведомления с
  соответствующей выдачей вручную
- Записать результат в чек-лист приёмки отдельно по каждому mapping и завести
  карточки на найденные дефекты

## Критерии приёмки

- [ ] End-to-end сценарий полностью проходится без обращения к базе и файлам
      отдельно для `igry-i-pristavki` и отдельно для `re.kufar.by/.../kvartiru`
- [ ] За время наблюдения нет пропусков ни у `igry-i-pristavki`-монитора, ни у
      `kvartiru`-монитора
- [ ] Дубли, если появились, объяснимы записью в журнале о повторной отправке из неопределённого состояния
- [ ] Перезапуск приложения не нарушает работу ни одного из двух активных
      мониторов
- [ ] Чек-лист содержит использованные реальные ссылки и отдельный результат по
      каждому из двух поддерживаемых route/category mappings; дефекты заведены
- [ ] Результат приёмки не расширяет обещание поддержки на `/elektronika`,
      real-estate categories вроде `doma` или другие Kufar routes без отдельного
      production routing + recon/contract evidence

## Не делать

- Не проверять тихие часы, сон машины, избранное и цены: они не входят в этот срез
- Не проверять установку на чистой машине: установочных пакетов до `5.7` не существует
- Не автоматизировать этот прогон: e2e-сценарии — задача `5.6.1`
- Не экстраполировать успешную приёмку `igry-i-pristavki` / `kvartiru` на всю
  электронику, всю недвижимость или другие категории Kufar; категория «Авто»
  явно вне периметра
