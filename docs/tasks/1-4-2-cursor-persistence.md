# Задача 1.4.2 — Персистентность водяного знака и граница транзакции

> Эпик 1.4 · Фаза 1 · ⬜ todo · зависит от: 1.4.1, 0.3.2 · оценка: 3-4 ч

## Цель

Сохранить водяной знак и записать найденное одной транзакцией, так, чтобы прерванный обход не приводил ни к дублям, ни к потерям.

## Контекст

Обход может прерваться посередине: приложение закрыли, машина уснула, сеть отвалилась. Запись должна быть устроена так, чтобы повтор был безопасен по построению, а не по удаче.

Ключевая гарантия, ради которой задача существует: **водяной знак нельзя продвинуть отдельно от результатов отбора**. Иначе получается тихая потеря: знак продвинулся, процесс упал, `Match` не создан, следующий обход считает объявление старым, уведомление не приходит никогда. Поэтому продвижение знака и запись результатов — одна транзакция, всегда.

Второе, что надо понимать: `Match` означает «объявление подошло под правило», а не «объявление увидели». Матчер ключевых слов появляется позже, в эпике `2.2`. Поэтому здесь строится транзакционная оболочка с шагом отбора, который пока пропускает всё, а `2.2` подставляет в этот шаг настоящий матчер, не трогая границы транзакции.

## Что должно быть сделано

- Реализовать конвейер обхода: страницы → водяной знак определяет кандидатов →
  шаг отбора → одна транзакция
- Реализовать сброс курсора при смене разобранного запроса монитора: правила
  сброса описаны в спецификации модели данных
- В транзакции: `upsert` каждого `Listing` по идентификатору площадки, вставка
  `Match` для прошедших отбор, обновление `MonitorCursor`, запись `Run`
- Шаг отбора на этом этапе — заглушка, пропускающая всех кандидатов; интерфейс
  шага должен позволить эпику `2.2` подставить настоящий матчер без изменения
  границ транзакции
- Вставка `Match` опирается на уникальное ограничение из `0.3.2`
- Покрыть интеграционными тестами: повторный прогон, прерывание до фиксации,
  прерывание после фиксации

## Критерии приёмки

- [ ] Повторный обход той же выдачи не создаёт вторых записей `Match`
- [ ] Прерывание до фиксации оставляет водяной знак прежним, объявления перечитываются на следующем обходе
- [ ] Невозможно состояние «водяной знак продвинут, `Match` не создан»: тест на прерывание между этими действиями показывает, что они атомарны
- [ ] Смена `sourceUrl` монитора сбрасывает курсор: следующий обход ведёт себя как холодный старт
- [ ] Смена интервала, имени или ключевых слов курсор не трогает
- [ ] Интеграционные тесты зелёные на чистой базе
