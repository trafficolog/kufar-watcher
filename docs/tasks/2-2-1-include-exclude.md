# Задача 2.2.1 — Правила include и exclude по полям

> Эпик 2.2 · Фаза 2 · ✅ done · зависит от: 2.1.3 · оценка: 3-4 ч

## Цель

TDD. Применить списки включающих и исключающих термов к полям объявления и вынести вердикт.

## Контекст

Логика короткая, но с неочевидной семантикой пустых списков: пустой include означает «проходят все», а не «не проходит никто». Ошибка здесь превращает работающий мониторинг ссылки в монитор, который молчит всегда.

## Что сделано

- Добавлен чистый `electron/worker/listing-matcher.ts` с вердиктом по спискам `include` / `exclude` и явным набором активных полей.
- Пустой `include` открывает include-gate; непустой требует хотя бы одного совпадения; любое совпадение `exclude` имеет приоритет и отклоняет объявление.
- Заголовок токенизируется через общий `tokenizeMatchingText()`, а каждый терм компилируется только через `matchingTermCompiler` из `2.1.3`.
- Результат возвращает `matched` и дедуплицированные hits с исходным термом, полем (`title` / `description`) и видом (`include` / `exclude`).
- Сигнатура уже допускает `description`, но MVP-1 активирует только `title`: наличие описания в документе само по себе не включает поиск по нему.
- Позиции совпадений, snippet, Prisma persistence и подключение к traversal намеренно оставлены задачам `2.2.2` и `2.2.3`.

## Критерии приёмки

- [x] Все случаи из тестов проходят
- [x] Пустой include не блокирует объявления
- [x] Exclude имеет приоритет над include
- [x] Результат содержит сработавшие термы и поле, в котором они найдены
- [x] Тесты написаны до реализации
