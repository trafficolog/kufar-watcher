# Задача 2.2.1 — Правила include и exclude по полям

> Эпик 2.2 · Фаза 2 · ⬜ todo · зависит от: 2.1.3 · оценка: 3-4 ч

## Цель

TDD. Применить списки включающих и исключающих термов к полям объявления и вынести вердикт.

## Контекст

Логика короткая, но с неочевидной семантикой пустых списков: пустой include означает «проходят все», а не «не проходит никто». Ошибка здесь превращает работающий мониторинг ссылки в монитор, который молчит всегда.

## Что должно быть сделано

- Сначала тесты: пустой include пропускает всё; непустой требует совпадения хотя бы по одному терму; exclude отбрасывает даже при сработавшем include; оба списка пусты; терм совпал в заголовке; терм совпал только в описании при выключенном поиске по описанию
- Реализовать вердикт по полям, доступным в срезе: в MVP-1 это заголовок
- Вернуть не только вердикт, но и список сработавших термов с указанием поля
- Заложить возможность добавить поле описания без изменения сигнатуры

## Критерии приёмки

- [ ] Все случаи из тестов проходят
- [ ] Пустой include не блокирует объявления
- [ ] Exclude имеет приоритет над include
- [ ] Результат содержит сработавшие термы и поле, в котором они найдены
- [ ] Тесты написаны до реализации

## Подсказки

- Семантика списков описана в `docs/superpowers/specs/matching-rules.md`
