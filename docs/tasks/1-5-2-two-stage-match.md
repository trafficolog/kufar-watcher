# Задача 1.5.2 — Политика загрузки описания

> Эпик 1.5 · Фаза 1 · ⬜ todo · зависит от: 1.5.1 · оценка: 2 ч

## Цель

Определить и реализовать единственное правило: когда описание объявления
загружается, а когда нет.

## Контекст

Правило простое, но к нему легко прийти неправильно. Напрашивается оптимизация:
если ключевое слово уже найдено в заголовке, описание ничего не решает, значит
запрос можно не делать. Она неверна. Описание нужно не только для вердикта —
если ключ встречается в описании, его фрагмент уходит в уведомление, и именно
так пользователь понимает, почему объявление пришло. Пропустив загрузку, мы
теряем этот фрагмент.

Дополнительный запрос на каждое новое объявление — осознанно принятая цена
возможности искать по описанию, а не то, что нужно оптимизировать.

Эпик `1.5` целиком относится к срезу `0.4.0`, а не к MVP-1: поиск по описанию
осмысленно ставить рядом с фильтром продавца, чтобы дешёвые отсевы работали
раньше дорогой загрузки.

## Что должно быть сделано

- Реализовать правило: поиск по описанию выключен в правиле — описание не
  загружается никогда; включён — загружается для каждого нового объявления,
  прошедшего водяной знак и все уже реализованные отсевы
- Загрузку выполнять после отсева по продавцу и дедупликации, чтобы не платить
  запросом за объявление, которое всё равно будет отброшено
- Использовать кеш из `1.5.1`: повторная загрузка одного объявления исключена
- Покрыть юнит-тестами обе ветви правила

## Критерии приёмки

- [ ] При выключенном поиске по описанию дополнительных запросов нет
- [ ] При включённом описание загружается для каждого нового объявления, включая те, что уже совпали по заголовку
- [ ] Загрузка выполняется после всех дешёвых отсевов, а не до них; при наличии фильтра продавца (эпик 2.3) объявление из чёрного списка описание не загружает
- [ ] Повторный обход не загружает описание второй раз
- [ ] Юнит-тесты на обе ветви зелёные

## Подсказки

- Полные правила отбора: `docs/superpowers/specs/matching-rules.md`
- Матчер целиком реализуется в эпике 2.2; здесь только порядок обращений к сети

## Не делать

- Не реализовывать сам матчер ключевых слов — это эпик 2.2
- Не вводить эвристики «когда описание вероятно не понадобится»: правило одно и
  оно детерминированное
