# Задача 1.3.2 — Адаптер «Электроника»

> Эпик 1.3 · Фаза 1 · ⬜ todo · зависит от: 1.3.1 · оценка: 4-6 ч

## Цель

Первый рабочий адаптер: запрос выдачи и нормализация ответа в доменную модель.

## Контекст

Гипотезы контракта проверены раньше, в эпике `1.0`, и задача опирается на снятые там фикстуры. Здесь проверяется другое: что нормализация выдерживает фактический ответ целиком, включая договорную цену, отсутствующие поля и вторую страницу. Расхождения с фикстурой фиксируются правкой спеки, а не подгонкой кода под догадку.

## Что должно быть сделано

- Опереться на фикстуры и уточнённую спеку из эпика `1.0`; при необходимости снять дополнительную фикстуру
- Сверить фактические имена полей со спецификацией контракта, обновить спеку по факту
- Нормализовать цену в пару «вид + сумма», корректно обработав договорную цену
- Реализовать запрос выдачи через клиент `1.2.2`, **с поддержкой курсорной
  пагинации**: адаптер умеет отдать следующую страницу по курсору
- Реализовать нормализацию в `Listing`, включая цену, валюту, регион, идентификатор продавца и признак юрлица
- Отсутствие обязательного поля — ошибка нормализации с указанием поля, а не тихое `undefined`
- Покрыть нормализацию тестами на фикстуре

## Критерии приёмки

- [ ] Запрос по реальной ссылке возвращает непустой список нормализованных объявлений
- [ ] Запрос второй страницы по курсору возвращает объявления, не пересекающиеся с первой
- [ ] Договорная цена нормализуется в `priceKind: negotiable` без потери объявления
- [ ] Все обязательные поля из спецификации контракта заполнены
- [ ] Спека контракта обновлена: пометки «требует проверки» сняты или уточнены
- [ ] Фикстура сохранена в `tests/fixtures/kufar/` с датой
- [ ] Тесты нормализации работают на фикстуре, без обращения к сети
