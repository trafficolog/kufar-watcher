# Задача 5.0.1 — Быстрое создание монитора

> Эпик 5.0 · Фаза 5 · ✅ done · зависит от: 2.4.1, 1.1.1 · оценка: 4-5 ч

## Цель

Экран, на котором пользователь создаёт правило: имя, ссылка, интервал, ключевые слова.

## Контекст

Без этого экрана срез MVP-1 не является пользовательским: правило пришлось бы заводить прямо в базе. Экран намеренно минимальный — полный редактор с предпросмотром и фильтрами приходит в `5.2` и расширяет этот же экран.

## Что должно быть сделано

- Форма: имя-тег, ссылка, интервал, списки включающих и исключающих термов
- Разбирать вставленную ссылку через `1.1.1` и показывать разобранный вид: категория, регион, поисковая строка
- Нераспознанная ссылка и ссылка на категорию вне периметра дают понятную ошибку прямо в форме
- Показать подсказку о поведении `*` и о том, что словоформы в этом срезе не ищутся
- Сохранение создаёт монитор и его расписание

## Критерии приёмки

- [x] Монитор создаётся из окна приложения без обращения к базе
- [x] Разобранный вид ссылки виден до сохранения
- [x] Ссылка на авто отклоняется с объяснением
- [x] После сохранения обход начинается по расписанию

## Результат

- `/monitors` содержит минимальную форму имени, Kufar URL, интервала и include/exclude термов и сохраняет правило через типизированный preload/IPC bridge без прямого доступа renderer к БД.
- URL до сохранения проходит существующие `parseKufarListingUrl` и `routeKufarQuery`; форма показывает категорию, регион и поисковую строку либо понятную inline-ошибку, включая отдельное объяснение для `auto.kufar.by`.
- Подсказка термов документирует `*` и отсутствие автоматического поиска словоформ; renderer только разбивает поле по запятым, а каноническая matching-валидация остаётся на backend boundary.
- Создание проходит через `createMonitorConfigAndSync`: монитор сохраняется в PostgreSQL и сразу передаётся в `MonitorScheduler` для reconciliation pg-boss schedule.
- PostgreSQL integration подтверждает сохранение canonical query/термов и реальное расписание `monitor-run/<id>` с ожидаемым cron; unit/contract tests покрывают renderer model, форму, preload/IPC, main/supervisor/worker wiring.
