# Задача 2.1.2 — Сопоставление glob-масок и литеральных термов

> Эпик 2.1 · Фаза 2 · ✅ done · зависит от: 2.1.1 · оценка: 3-4 ч

## Цель

TDD. Реализовать сопоставление терма с текстом: точное совпадение для обычного терма и маска для терма с `*`.

## Контекст

Это поведение, обещанное в срезе MVP-1 под словами «простые слова и маски». Маска должна работать предсказуемо и не превращаться в регулярное выражение: символы, значимые в регэкспах, обязаны экранироваться, иначе терм вроде `iphone (новый)` уронит сопоставление или найдёт не то.

## Что сделано

- Добавлен чистый модуль `electron/worker/matching-term.ts` с `compileMatchingTerm()` — компиляцией одного элемента `keywords` в предикат по одному уже нормализованному токену.
- Терм проходит общий `normalizeMatchingText()` из `2.1.1`; отдельной ветки нормализации для правил нет.
- Терм без `*` сравнивается строгим равенством, поэтому `колонка` не совпадает с `колонки`.
- Терм с `*` компилируется в якорный regex для целого токена: literal-части экранируются, и только `*` получает wildcard-семантику `.*`.
- Поддержаны `*` в начале, конце, внутри терма и несколько `*`; скобки, точка, плюс и остальные regex-спецсимволы остаются литеральными.
- Phrase matching для строк с пробелами, include/exclude matcher, интерфейс выбора реализации и морфология намеренно не добавлялись: это отдельные задачи `2.1.3`, `2.2` и `2.6`.

## Критерии приёмки
