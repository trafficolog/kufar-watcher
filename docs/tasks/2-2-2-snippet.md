# Задача 2.2.2 — Извлечение фрагмента вокруг совпадения

> Эпик 2.2 · Фаза 2 · ✅ done · зависит от: 2.2.1 · оценка: 2-3 ч

## Цель

Вернуть короткий фрагмент текста вокруг найденного терма для вставки в уведомление.

## Контекст

Фрагмент нужен, чтобы пользователь понимал, почему объявление пришло. В MVP-1 поиск идёт по заголовку, и фрагмент чаще всего совпадает с ним целиком; модуль всё равно пишется сейчас, потому что с приходом поиска по описанию он становится обязательным, а его интерфейс влияет на форматтер сообщения.

## Что сделано

- Общая matching-токенизация расширена span-aware API: нормализованные токены сохраняют `start` / `end` относительно исходного текста, включая полную форму и части токена с дефисом.
- `ListingMatchHit` расширен координатами совпадения; matcher возвращает span первого совпавшего token для каждой пары term/field, не меняя include/exclude semantics `2.2.1`.
- Добавлен чистый `electron/worker/matching-snippet.ts`, который строит один фрагмент вокруг самого раннего include-hit выбранного поля.
- Фрагмент расширяется только по границам слов, сохраняет исходные регистр и пунктуацию и добавляет `…` только с реально обрезанных сторон.
- Короткий title, целиком помещающийся в лимит, возвращает `null`, чтобы не дублировать заголовок в уведомлении.
- Подсветка совпадения, форматтер сообщения и подключение matcher/snippet в traversal намеренно оставлены задачам `3.2.1` и `2.2.3`.

## Критерии приёмки

- [x] Фрагмент не разрывает слова
- [x] Совпадение в коротком заголовке фрагмента не порождает
- [x] Несколько совпадений дают один фрагмент вокруг первого
- [x] Юнит-тесты зелёные
