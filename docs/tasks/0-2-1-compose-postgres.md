# Задача 0.2.1 — docker-compose с Postgres 16

> Эпик 0.2 · Фаза 0 · 🔄 in_progress · зависит от: 0.1.1 · оценка: 1-2 ч

## Цель

Описать контейнер Postgres 16 с постоянным томом и публикацией порта только на локальный адрес.

## Контекст

База живёт на машине пользователя и должна переживать перезапуски приложения и обновления образа. Публикация порта наружу не нужна и является лишним риском.

Важно понимать, что здесь на кону. Находки восстановимы повторным обходом, а история цен, архив мониторов и объявления, уже снятые с площадки, — нет. Том обязан быть именованным и переживать пересоздание контейнера.

## Что должно быть сделано

- Написать `docker-compose.yml` с Postgres 16 и именованным томом
- Опубликовать порт только на `127.0.0.1`
- Задать healthcheck контейнера через `pg_isready`
- Параметры подключения брать из `.env`; пароль генерируется при первой установке, а не хардкодится

## Критерии приёмки

- [ ] `docker compose up -d` поднимает базу, healthcheck становится healthy
- [ ] Данные переживают `docker compose down` и повторный подъём
- [ ] Порт недоступен с других машин в сети
- [ ] В репозитории нет реального пароля

## Подсказки

- Общий контекст — в карточке эпика и в `docs/AGENTS.md`

## Не делать

- Не заводить pgAdmin, Redis и прочие сервисы — в проекте одна база
- Не настраивать автоматическое резервное копирование: достаточно ручного экспорта, он делается в задаче эпика `5.4`
