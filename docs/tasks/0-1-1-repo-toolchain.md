# Задача 0.1.1 — Инициализация репозитория и тулчейна

> Эпик 0.1 · Фаза 0 · 🔄 in_progress · зависит от: — · оценка: 2-3 ч

## Цель

Создать репозиторий, где Electron и Nuxt 4 собираются вместе: main и preload через electron-vite, renderer — Nuxt в режиме SPA.

## Контекст

Нулевая точка проекта. Всё дальнейшее собирается этим тулчейном, поэтому ошибки конфигурации здесь дорого исправлять позже — особенно нативные модули, которые ломают сборку Electron.

Отдельно про renderer. Готового шаблона «electron-vite + Nuxt» не существует: у electron-vite есть `vue-ts`, `react-ts` и подобные, но не Nuxt. Соблазн взять шаблон `vue-ts` и «потом мигрировать» надо погасить сразу — это переписывание renderer в первой же задаче. Собирать связку нужно вручную, и это осознанная стоимость примерно часа настройки.

Ещё важнее, как собранная статика попадает в окно. Напрашивается `loadFile` и `file://` — и это неверный выбор по двум причинам сразу. Во-первых, у `file://` особые привилегии и непривычная модель происхождения, из-за чего рекомендации по безопасности Electron советуют не отдавать по ней страницы приложения. Во-вторых, у нас настоящие маршруты (`/monitors`, `/feed`, `/settings#seller-blacklist`), а по `file://` относительные пути и перезагрузка на вложенном маршруте ведут себя не так, как на dev-сервере.

Хэш-маршрутизация проблему тоже не решает: фрагмент уже занят якорем `#seller-blacklist`. Поэтому канонический путь — собственная схема, зарегистрированная как стандартная, с откатом неизвестного пути на `index.html`.

## Что должно быть сделано

- Развести дерево: `electron/main/`, `electron/preload/`, `app/` (Nuxt), `nuxt.config.ts` в корне
- Настроить Nuxt 4 с `ssr: false` — сервер рендерить нечего, нужен клиентский бандл
- Настроить electron-vite на сборку только main и preload; renderer собирает Nuxt
- В разработке: Nuxt поднимает свой dev-сервер, окно Electron открывает его адрес
- В сборке: `nuxt generate` кладёт статику в `.output/public/`, окно грузит её
  через **собственную схему, зарегистрированную как стандартная** (например
  `app://kufar/`), а не через `file://`
- Обработчик схемы отдаёт файл по пути, а неизвестный путь приложения —
  `index.html`: маршрутизацию дальше разбирает сам Nuxt
- Подключить Pinia
- Включить `strict: true` и запретить неявный `any` в конфигурации TypeScript
- Настроить ESLint и Prettier, добавить npm-скрипты `lint`, `typecheck`, `test`
- Подключить Vitest, добавить один заглушечный тест, чтобы раннер был проверен
- Создать `.env.example` с переменными БД и токеном бота; `.env` — в `.gitignore`

- [ ] Собранное приложение открывает интерфейс без dev-сервера
- [ ] Renderer в сборке обслуживается собственной схемой, `file://` не используется
- [ ] Прямое открытие и перезагрузка на `/monitors` и `/settings` работают в собранном приложении
- [ ] Якорь `#seller-blacklist` доводит до нужного места раздела после перезагрузки
- [ ] `npm run typecheck` и `npm run lint` возвращают ноль ошибок
- [ ] `npm test` проходит на заглушечном тесте
- [ ] В `.gitignore` есть `.env`, `node_modules`, каталог сборки
