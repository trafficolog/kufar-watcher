# Задача 3.1.1 — Бот на grammY и привязка чата

> Эпик 3.1 · Фаза 3 · ⬜ todo · зависит от: 0.1.2 · оценка: 3-4 ч

## Цель

Поднять бота на long-polling и связать его с единственным разрешённым чатом.

## Контекст

Вебхук невозможен: у домашней машины нет постоянного адреса. Привязка к одному чату — не только удобство, но и защита: бот, отвечающий любому, кто его нашёл, отдаёт посторонним содержимое чужих мониторов.

Отсюда следует, что привязывать первый написавший чат автоматически нельзя. Имя бота угадываемо, и тот, кто напишет раньше хозяина, получит поток его находок — с адресами, ценами и городом. Поэтому связь между человеком за приложением и чатом должна быть доказана действием в самом приложении, а не фактом сообщения.

Достаточно простейшей формы: сообщение делает чат кандидатом, приложение показывает, кто это, человек нажимает «Привязать». Вариант с одноразовым кодом в `/start <код>` тоже годится и удобнее, но для персонального приложения подтверждение кнопкой закрывает риск полностью.

## Что должно быть сделано

- Поднять grammY на long-polling в процессе воркера
- Реализовать привязку в два шага: сообщение боту делает чат **кандидатом**,
  привязка происходит только после явного подтверждения в окне приложения
- До подтверждения кандидат не получает ничего, кроме ответа о том, что запрос
  принят: содержимое мониторинга в непривязанный чат не уходит
- Привязка сохраняется в `Setting`, кандидат — нет
- Отбрасывать любые сообщения и нажатия кнопок из непривязанных чатов, без ответа
- Токен читать из защищённого хранилища, не из файла; отсутствие токена — понятное состояние, а не падение

## Критерии приёмки

- [ ] Бот принимает команды только из привязанного чата
- [ ] Чат, написавший боту, не получает находок до подтверждения в приложении
- [ ] Подтверждение доступно только в окне приложения, не из переписки
- [ ] Сообщение из чужого чата игнорируется молча
- [ ] Отсутствие токена не роняет воркер
- [ ] Токен не появляется в журнале ни на одном уровне
