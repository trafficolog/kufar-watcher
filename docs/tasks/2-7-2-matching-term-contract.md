# Задача 2.7.2 — Контракт термов и симметричная нормализация

## Проблема

Текст токенизируется с удалением краевой пунктуации, а term компилируется из нормализованной строки целиком. Поэтому `(ps5)` и `ps5` нормализуются несимметрично, а многословный term вроде `playstation 5` молча сравнивается с одним token и никогда не совпадает.

## Решение для текущего среза

MVP работает с отдельными словами и glob-масками, а не с phrase search. Многословный term должен быть явно отклонён, а не превращаться в скрытый always-false matcher. Нормализация term и token должна использовать один семантический путь при сохранении `*` как glob-оператора.

## Критерии приёмки

- [ ] RED фиксирует текущие failures для краевой пунктуации term и silent multiword term.
- [ ] `ps5`, `(ps5)` и token с эквивалентной краевой пунктуацией сравниваются симметрично.
- [ ] После нормализации term с пробельным разделением более чем на один token отклоняется явной validation error.
- [ ] Glob `playstation*` сохраняет текущую семантику; `*` не съедается punctuation normalization.
- [ ] Include и exclude используют одинаковый compiler contract.
- [ ] Пустой term после нормализации остаётся ошибкой.
- [ ] Спецификация и будущая UI-подсказка явно говорят: один term = один token в текущем срезе.

## Не делать

- Не добавлять phrase search или regex.
- Не смешивать эту задачу с морфологией эпика `2.6`.
