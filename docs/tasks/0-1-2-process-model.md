# Задача 0.1.2 — Процессная модель main + utilityProcess

> Эпик 0.1 · Фаза 0 · ✅ done · зависит от: 0.1.1 · оценка: 3-4 ч

## Цель

Развести приложение на три процесса: `main` держит окно и жизненный цикл, `utilityProcess` исполняет всю фоновую работу, `renderer` рисует интерфейс.

## Контекст

Мониторинг обязан продолжаться при закрытом окне и не подтормаживать интерфейс во время обхода. Если фоновая работа окажется в `main`, оба свойства теряются, а разнести их потом — переписывание половины приложения. Поэтому граница проводится сразу, до появления какой-либо логики.

## Что должно быть сделано

- Поднять `utilityProcess` из `main` при старте приложения
- Реализовать корректное завершение: воркер получает сигнал остановки, доводит текущую операцию и закрывается
- Реализовать перезапуск воркера при аварийном падении, с ограничением частоты перезапусков
- Вынести в воркер точку входа с заглушкой планировщика — реальные джобы появятся в эпике 2.4
- `contextIsolation: true`, `nodeIntegration: false` для окна

## Критерии приёмки

- [x] Закрытие окна не завершает процесс воркера
- [x] Завершение приложения через трей корректно останавливает воркер, без осиротевших процессов
- [x] Падение воркера приводит к его перезапуску, событие пишется в журнал
- [x] Более трёх падений подряд переводят приложение в состояние ошибки, а не уходят в цикл перезапусков

## Проверка 2026-09-06

- CI run `34033463696`: `npm ci`, unit, typecheck, lint, format, build, dev smoke и production smoke — зелёные.
- Dev и production smoke требуют фактическое событие `[worker] ready` от `utilityProcess`.
- Crash/restart, backoff `1s → 2s → 4s`, fatal после четвёртого последовательного падения и graceful shutdown handshake покрыты unit-тестами.
- В `main` нет `window-all-closed → app.quit()`, поэтому закрытие единственного окна не инициирует shutdown воркера. Карточка рекомендует дополнительно повторить этот сценарий вручную в реальном desktop-сеансе.
- UI трея не реализован намеренно (`5.1.1`). Общий путь завершения приложения реализован через `before-quit`; будущая команда Exit из трея должна использовать этот lifecycle.

- Проверять поведение при закрытии окна нужно вручную: автотестами это ловится плохо
