# Задача 2.1.3 — Интерфейс сопоставления с одной реализацией

> Эпик 2.1 · Фаза 2 · ✅ done · зависит от: 2.1.2 · оценка: 2 ч

## Цель

Объявить интерфейс сопоставления терма с текстом и подключить к нему единственную пока реализацию.

## Контекст

Морфология приходит срезом `0.4.0` как вторая реализация. Если её место не подготовить сейчас, эпик `2.6` придётся вживлять в уже написанный матчер и переписывать его тесты. Интерфейс здесь дешёвый и оправданный: вторая реализация не гипотетическая, она уже запланирована и описана.

## Что сделано

- Добавлен `electron/worker/matching-term-compiler.ts` с типом `MatchingTermPredicate` и интерфейсом `MatchingTermCompiler`, который компилирует терм в предикат по нормализованному токену.
- Экспорт `matchingTermCompiler` является единственной явной composition point для выбора реализации и делегирует в проверенный `compileMatchingTerm()` из `2.1.2`.
- Все тесты поведения `2.1.2` переведены с прямого вызова concrete implementation на `matchingTermCompiler.compile()`.
- Contract-test с альтернативным `MatchingTermCompiler` подтверждает, что consumer-код работает через контракт и не требует изменения при подстановке другой реализации.
- Матчер из `2.2` намеренно не создавался раньше своей карточки: его публичной зависимостью будет composition module, а не `matching-term.ts`.
- Заготовка stemmer, mode enum, отдельный package и гипотетическая factory не добавлялись; ветка выбора второй реализации появится в этой одной точке вместе с `2.6`.

## Критерии приёмки

- [x] Матчер зависит от интерфейса, а не от конкретной реализации
- [x] Добавление второй реализации не требует правки вызывающего кода
- [x] Тесты `2.1.2` работают через интерфейс
