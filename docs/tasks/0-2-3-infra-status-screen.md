# Задача 0.2.3 — Экран состояния инфраструктуры

> Эпик 0.2 · Фаза 0 · 🔄 in_progress · зависит от: 0.2.2, 0.1.3 · оценка: 2-3 ч

## Цель

Полноэкранное состояние инициализации: на каком шаге находится запуск, чем он закончился и что делать, если не удалось.

## Контекст

Первое, что видит пользователь при запуске. Если база поднимается десять секунд, он должен понимать, что происходит; если Docker выключен — получить инструкцию, а не код ошибки.

Ловушка здесь в том, что не всякий несостоявшийся шаг — отказ. На самом первом запуске Telegram заведомо не настроен: токен человек введёт позже, ради этого и существует состояние первого запуска. Если считать это ошибкой, приложение встретит нового пользователя красным экраном в единственно нормальной для него ситуации.

## Что должно быть сделано

- Отобразить последовательность шагов запуска с текущим состоянием каждого
- Для ошибки «демон недоступен» показать подсказку: запустить Docker Desktop и повторить
- Добавить три выхода при отказе: повторить, открыть журнал, выйти
- Показывать исход каждого шага, а не только текущий: Docker, база, миграции,
  планировщик, Telegram
- Развести шаги по весу отказа, иначе первый же запуск окажется «неуспешным»:

  | Шаг | Отказ означает |
  |-----|----------------|
  | Docker, база, миграции, планировщик | запуск невозможен: писать находки некуда |
  | Telegram не настроен | шаг пропущен, запуск продолжается — токена на первом запуске ещё нет |
  | Telegram настроен, но сеть недоступна | деградация: приложение открывается, уведомления копятся в очереди |

- Текст ошибки Docker зависит от платформы: на Windows проверяют Docker Desktop,
  на Linux — службу демона и доступ к сокету
- После успешного завершения перейти к основному окну
