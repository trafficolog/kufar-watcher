# Задача 0.1.3 — Типизированный IPC-контракт

> Эпик 0.1 · Фаза 0 · ✅ done · зависит от: 0.1.2 · оценка: 3-4 ч

## Цель

Один типизированный контракт обмена сообщениями между `main`, воркером и `renderer`, с общим пакетом типов.

## Контекст

Три процесса обмениваются данными, и без единого описания сообщений типы неизбежно разъедутся. Контракт задаётся один раз и переиспользуется обеими сторонами, чтобы изменение формы сообщения ломало сборку, а не поведение в рантайме.

## Что должно быть сделано

- Создать общий модуль типов домена и сообщений, доступный всем трём процессам
- Описать каналы: команды от renderer, ответы, поток событий от воркера
- Реализовать preload-мост с явно перечисленными методами, без проброса `ipcRenderer` наружу
- Реализовать маршрутизацию сообщений renderer ↔ main ↔ worker
- Покрыть сериализацию и маршрутизацию юнит-тестами

## Критерии приёмки

- [x] Renderer не имеет доступа к Node API, только к перечисленным методам моста
- [x] Добавление поля в тип сообщения вызывает ошибку компиляции на обеих сторонах
- [x] Событие, отправленное воркером, доходит до renderer
- [x] Юнит-тесты на маршрутизацию зелёные

## Подсказки

- Список каналов на старте минимальный: состояние подсистем и журнал событий. Остальное добавляется по мере надобности

## Не делать

- Не проектировать каналы под будущие экраны фазы 5 заранее
