# Задача 1.2.2 — Клиент: таймауты, ретраи, обработка ошибок

> Эпик 1.2 · Фаза 1 · ✅ done · зависит от: 1.2.1 · оценка: 3-4 ч

## Цель

Сетевой клиент поверх лимитера: таймауты, ретраи с экспоненциальной задержкой, различение временных и постоянных ошибок.

## Контекст

Сеть на домашней машине нестабильна: смена сети, засыпание, обрывы. Временный сбой не должен выглядеть как поломка площадки, а поломка площадки не должна маскироваться бесконечными ретраями.

## Что должно быть сделано

- Реализовать клиент на undici с таймаутами соединения и ответа
- Ретраи с экспоненциальной задержкой для сетевых ошибок и `5xx`; количество попыток ограничено
- Ответ `429` — увеличить временную глобальную паузу лимитера и вернуть явный
  `rate-limited` outcome наверх. Ретраи и переход на фолбэк при `429` запрещены.
  Фактическая запись этого outcome в `Run.outcome` / `Run.error` принадлежит
  задаче `2.4.3`; `HealthEvent` в этой задаче не создаётся
- Ошибки `4xx`, кроме `429`, считать постоянными и не ретраить
- Возвращать структурированный результат с классификацией исхода, а не бросать голое исключение

## Критерии приёмки

- [x] Временный сбой сети приводит к успеху после ретрая
- [x] Постоянная ошибка возвращается сразу, без исчерпания попыток
- [x] Ответ `429` приводит к снижению темпа и явному сигналу наверх
- [x] Все запросы проходят через лимитер из `1.2.1`

## Результат — 2026-09-07

- `KufarHttpClient` выполняет GET через один глобальный limiter; каждый retry снова проходит через тот же `schedule()`.
- Production transport использует explicit Undici `Agent` с таймаутами `10s/15s/30s` для connect/headers/body; redirect interceptor не подключён, поэтому `3xx` возвращается policy-client напрямую; body сохраняется raw `Uint8Array`.
- Network/timeout/`5xx` получают максимум три HTTP attempts с backoff `500ms -> 1000ms`; `4xx` кроме `429` и неожиданные статусы не ретраятся.
- `429` не ретраится и не переключается на fallback; `Retry-After` управляет временным global cooldown, default `60s`, максимум `15m`.
- Клиент возвращает structured outcomes; Prisma/`Run`, raw journal, fallback, scheduler retries и schema parsing остаются владельцам последующих задач.
